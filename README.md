# Simulated Typing

一个规避编辑器自动补全的「模拟打字」工具。运行后常驻系统托盘，当你在任意
编辑器里按下 **Ctrl+V** 或 **Ctrl+Shift+V** 时，软件不会执行常规粘贴，而是
读取当前剪贴板中的文本，逐个字符地模拟真实打字。

## 防自动补全的按键规则

模拟开始时先注入占位字符 <kbd>X</kbd> 并把光标移到它左侧，此后剪贴板内容
逐字符插入在 X 之前——第一个内容键不再是行首，编辑器不会弹出自动补全；
模拟结束或被中止时注入 <kbd>Delete</kbd> 删除占位的 X，文档中只留下真正
的内容。

| 模拟阶段 | 模拟的按键 |
|----------------|------------|
| 开始 | <kbd>X</kbd> → <kbd>←</kbd>（放置占位符） |
| 换行符（`\r\n`、`\n` 或孤立的 `\r`） | <kbd>Enter</kbd> → <kbd>Space</kbd> → <kbd>Shift</kbd>+<kbd>Ctrl</kbd>+<kbd>←</kbd> → <kbd>Backspace</kbd> |
| 制表符（`\t`） | <kbd>Tab</kbd> 键 |
| 其他任意字符（含中文） | 字符本体（Unicode 注入） |
| 结束 / 中止 | <kbd>Delete</kbd>（删除占位 X） |

中止时若占位 X 尚未放置（只打了 X、还没打 ←），会以 Backspace 撤销它而
不是 Delete；换行后尚未删除的辅助 Space 也会被补删。

## 行为细节

- **剪贴板为空或当前内容不是文本**（如复制的文件、图片）时，Ctrl+V
  原样放行，保持系统常规粘贴行为。
- **打字速度** 默认 10 毫秒/键；可在托盘菜单中修改，设置保存在注册表
  `HKCU\Software\SimulatedTyping\SpeedMs`，下次启动自动恢复。
- **中止模拟**：粘贴很长的文本时，模拟期间随时按下 <kbd>Esc</kbd> 可立即
  停止剩余内容的输入（自动撤销未就位的占位 X、补删换行后的辅助空格；
  占位 X 已就位时由结尾 <kbd>Delete</kbd> 删除），已完整打出的内容保留。
- **输入封锁**：模拟进行期间屏蔽所有物理键盘与鼠标输入（含鼠标移动、
  点击、滚轮，也包括 <kbd>Esc</kbd> 本身），防止杂散输入混进目标文档；
  <kbd>Esc</kbd> 仅由本软件消费用于中止模拟，不会传达给目标程序。封锁
  期间托盘菜单也无法点击，中止或退出的唯一途径是 <kbd>Esc</kbd>（先中止
  再操作托盘）；来自其他软件的注入输入（屏幕键盘、自动化工具等）不在
  封锁范围内。
- **超大文本**：剪贴板文本约超过 100 万字符时不模拟（以默认速度逐字打出
  需要数小时），Ctrl+V 按常规粘贴执行。
- 模拟进行中所有 V 键按下都会被忽略（包括再次的 Ctrl+V）；本次模拟结束
  并松开触发用的 V 键后恢复响应。
- 「启用」开关每次启动都默认为勾选（该状态不持久化）；速度设置则持久化。
- 同一登录会话内只允许运行一个实例。

## 托盘菜单（左键单击图标）

- **启用**：可勾选的总开关，软件启动后默认勾选。取消勾选期间 Ctrl+V
  保持系统常规粘贴行为，重新勾选后恢复模拟打字。
- **修改打字速度**：输入非负整数，单位毫秒/键，默认 10（上限 3600000，
  超出会被拒绝）。
- **退出 Simulated Typing**：立即结束软件。

## 构建要求与步骤

- Windows 10/11
- Visual Studio 2017 及以上（或 Build Tools），需包含
  「使用 C++ 的桌面开发」工作负载（MSVC + Windows SDK）

在仓库根目录执行：

```bat
build.bat
```

脚本通过 vswhere 自动定位最新的 MSVC，先编译并运行单元测试（失败即止），
再编译资源与源码，全部通过则在根目录生成 `SimulatedTyping.exe`。

## 使用注意

- 若目标编辑器**以管理员身份运行**，本软件也需要以管理员身份运行才能向其
  注入按键（Windows 的 UIPI 限制；被拦截时按键可能被静默丢弃且不报错）。
- 软件对剪贴板只读取 `CF_UNICODETEXT` 格式；没有该格式的剪贴板内容
  （如文件、图片）会按常规粘贴放行。
- exe 静态链接 C 运行时（/MT），无需安装 VC++ Redistributable 即可直接运行。
- 已知限制：
  - 由注入方式输入的按键（屏幕键盘 osk、AutoHotkey 等自动化工具）不会被
    识别为 Ctrl+V 触发，表现为常规粘贴。
  - AltGr（欧洲）键盘布局下，打字期间按过 AltGr 后可能需要重新按一次
    Ctrl 才能再次触发模拟。
  - 系统负载极端时键盘钩子可能错过单个修饰键事件，表现为触发暂时失灵，
    重按一次对应的修饰键即可恢复。
  - 其他软件的键盘钩子若拦截按键且不向下转发，可能影响本软件触发；
    遇到时重启本软件。
  - 目标窗口处于输入法组字（拼音未上屏）状态时，模拟按键可能被输入法
    消费，导致行为异常；请先让候选词上屏再触发粘贴。
